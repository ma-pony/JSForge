# DeepSpider

[![npm version](https://img.shields.io/npm/v/deepspider.svg)](https://www.npmjs.com/package/deepspider)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

DeepSpider is a DSH-native JavaScript reverse-engineering platform. Patchright Chromium and CDP collect real requests, scripts, and runtime evidence. DeepSpider then recovers the critical logic as JavaScript or Python that can run offline and be verified against the real request.

The browser supplies evidence. The finished deliverable explains the parameter-generation chain and sends the target request without depending on page automation.

[中文](README.md)

## Quick start

DeepSpider requires Node.js `>=24.15.0`. Global installation downloads Patchright Chromium.

```bash
npm install -g deepspider
deepspider agent
```

DSH Web loads the Spider Preset. Create a Session and describe the target request, its page trigger, and the required JavaScript or Python deliverable. Multiple Sessions can run concurrently with separate browsers, SessionArtifactStores, and artifact roots.

```bash
deepspider agent --port 3080 --verbose
```

`Ctrl+C` closes DSH Web, every DeepSpider Runtime, and its associated browser.

## Definition of done

A reverse-engineering task should deliver:

- target request and script evidence captured by the Browser Oracle;
- an explicit Output Contract and Session-owned Runtime Recipe;
- the target output generated by an independent Node Worker;
- a real request using only generated values, accepted at the `reproduced` evidence level;
- a Solver that runs without the Browser Session.

A capture, page-automation script, or single Hook log is evidence for the investigation. It is not a completed reverse-engineering result.

## Semantic recovery

```text
Browser Oracle → Artifact Graph → Output Contract → Runtime Recipe → Worker → Request Validation → Solver
```

| Phase | Action | Contract |
| --- | --- | --- |
| Browser Oracle | Open the page and capture network, scripts, and property facts | Browser output remains `observed` evidence |
| Artifact Graph | Link Documents, Scripts, requests, responses, and dynamic sources | Keep all evidence inside the Session |
| Output Contract | Select Cookie, Header, Query, Body, return value, or navigation output | Bind status and content success conditions |
| Runtime Recipe | Declare fixed values, concealment, and execution boundaries | Keep site rules in the Session instead of core branches |
| Worker | Execute the target with fresh state | Never read Patchright Cookies or browser-data |
| Request Validation | Send the real request using only Worker-generated values | Mark success as `reproduced` only after acceptance |
| Solver | Export the Contract, Recipe, and standalone entry point | Rerun without the associated browser |

The Patchright-controlled Session is an important sample, not an absolute browser truth. For fingerprint or timing questions, compare it with regular Chrome, multiple Sessions, or confirmed target behavior.

### Runtime Recipe

`recover_target_output` builds an Output Contract from the current Session evidence and executes a Runtime Recipe in an independent Worker. The Recipe declares:

- fixed values and confirmed site rules;
- concealed property paths;
- window proxy configuration;
- User-Agent, TLS policy, and bounded timeout.

Stable fingerprint or site-specific rules may stay in the Session Recipe when that is the simplest reliable implementation. The Patchright Session is evidence, not absolute browser truth; compare sensitive fingerprints with regular Chrome, multiple Sessions, or confirmed target behavior.

### Observed and derived artifacts

Captured scripts, responses, and dynamic sources are immutable `observed` Artifacts. Formatting, deobfuscation, or targeted changes create a new `derived` Artifact with its source Artifact ID and content hash. Worker outputs are `generated` Artifacts; only successful request validation raises the evidence to `reproduced`.

### Eight-stage reverse-engineering workflow

```text
intake → evidence → locate → recover → runtime → extraction → validation → handoff
```

| Stage | Task | Output |
| --- | --- | --- |
| intake | Define the request, trigger path, and delivery requirement | Structured objective |
| evidence | Reproduce and inspect the complete request and response | Request-chain evidence |
| locate | Follow the Initiator, call stack, and source to the write boundary | Parameter origin |
| recover | Recover bridge contracts and critical operators | Callable function |
| runtime | Find the first browser/local divergence | Environment Recipe |
| extraction | Separate the algorithm from the runtime | Standalone implementation and fixtures |
| validation | Compare multiple inputs and real requests | Verification record |
| handoff | Assemble entry points, configuration, and instructions | Runnable crawler or request module |

## DSH Agent capabilities

- **Sessions** run multiple tasks concurrently with isolated browsers and files.
- **Goals and Todo** hold the task objective and current execution items.
- **Code Mode** uses `run_code` and the generated TypeScript SDK to call DeepSpider tools.
- **Cordis dynamic tools** inspect and invoke runtime capabilities within the current Agent permissions.
- **Web Search** finds public references; DeepSpider browser tools remain the source of page evidence.
- **Dialog** is an optional in-page panel for chat, element or iframe selection, and native DSH single-choice, multiple-choice, and custom answers.

`browser_dialog` opens or sends data only when the current Session already owns a browser. Answers return to that same DSH Session. Opening Dialog does not activate Probe.

## Usage

| Command | Purpose |
| --- | --- |
| `deepspider agent [--port <number>] [--verbose]` | Start native DSH Web and the Spider Preset |
| `deepspider mcp` | Start the stdio MCP external adapter |
| `deepspider fetch <url>` | Make one lightweight HTTP request through CycleTLS |
| `deepspider update` | Check for and update a global installation |
| `deepspider --version` | Show the version |
| `deepspider --help` | Show help |

`fetch` does not launch a browser or enter the Agent workflow. The MCP stdio adapter serves external clients that need direct access to the DeepSpider catalog. Use DSH Web for the complete multi-Session workflow.

## Tool catalog

DSH and MCP receive the same central catalog. Its size is derived from code and is not fixed in documentation.

| Group | Capabilities |
| --- | --- |
| Browser | Page actions, tabs and iframes, screenshots, DOM, storage, console, Dialog |
| Network | Requests, responses, Initiator data, WebSockets |
| Script | Script inventory, complete source retrieval, cross-script search |
| Debugger | Breakpoints, call stacks, stepping, evaluation, logpoints |
| Hook | Explicit injection and runtime log queries |
| Stealth | Anti-debug interception control |
| Capture | Browser environment, descriptors, prototypes, and function facts |
| Recovery | `recover_target_output` performs independent generation, real request validation, and Solver export |

## Artifacts

Each Agent Session owns this root:

```text
~/.deepspider/sessions/<sha256(agent.id)>/
├── metadata/
├── data/                 # SessionArtifactStore request, response, and script indexes
├── evidence/
├── contracts/
├── recipes/
├── runs/
├── validations/
├── solvers/
├── screenshots/
└── browser-data/
```

Each successful recovery creates a standalone directory under `solvers/` with:

```text
solver.mjs
contract.json
recipe.json
package.json
```

## Architecture

```text
DSH Web Host Plane
├── Sessions, models, Goals, Todo, Cordis, and event routing
└── Spider Agent Plane
    ├── Code Mode + DeepSpider Catalog
    └── Session-owned DeepSpider Runtime
        ├── Patchright Chromium + CDP
        ├── Dialog + Browser Oracle
        ├── SessionArtifactStore + Artifact Graph
        └── sdenv Worker + CycleTLS Validator + Solver

MCP stdio adapter
└── the same DeepSpider Catalog
```

The Host Plane owns application-level services and multiple Sessions. An Agent Plane performs one Session's reverse-engineering work. RuntimeManager enforces their state boundaries.

## Run from source

Development uses Node.js `>=24.15.0` and pnpm `11.21.0`.

```bash
git clone https://github.com/ma-pony/deepspider.git
cd deepspider
pnpm install

node bin/cli.js agent --port 3080 --verbose
```

For a headless browser:

```bash
export DEEPSPIDER_HEADLESS=true
```

Release checks:

```bash
pnpm test
pnpm lint
pnpm audit --prod
pnpm test:integration
pnpm smoke:pack
npm pack --dry-run
```

Integration tests require an environment that permits Patchright Chromium child processes. DeepSpider does not load a project-root `.env` automatically.

## Security and authorization

DSH stores model-provider settings and credentials. DeepSpider bundles no accounts. Cordis, browser debugging, script execution, and network access are privileged capabilities for trusted tasks. Analyze only targets that you own or are authorized to assess, and comply with target terms and applicable law.
